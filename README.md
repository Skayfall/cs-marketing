# CS Marketing by skayfall

Внутренний маркетинговый центр ПТГ «Центр Сантехники»: сайт, SEO, реклама, соцсети, email, рекомендации, задачи и отчётность.

## Доступ

В версии 0.2 добавлена серверная авторизация.

- логин: `admin`;
- пароль: `csmarketing`;
- сессия действует 12 часов;
- cookie авторизации — `HttpOnly`, `SameSite=Strict` и `Secure` на HTTPS;
- без действующей сессии `/api/status`, `/api/dashboard`, импорт и ручная синхронизация возвращают `401`;
- пароль не хранится во фронтенде и должен быть добавлен в Cloudflare Secret `ADMIN_PASSWORD`;
- подпись сессии хранится в отдельном Secret `SESSION_SECRET`.

Сейчас один аккаунт можно использовать на двух устройствах одновременно — например, маркетологу и руководителю. Архитектура позволяет позже добавить отдельные аккаунты и роли `admin / viewer`.

## Что уже работает

## Быстрый локальный запуск

Авторизация теперь серверная, поэтому просто открывать `public/index.html` двойным кликом нельзя.

1. Установить Node.js 20+.
2. В папке проекта выполнить:

```bash
npm install
cp .dev.vars.example .dev.vars
npm run db:local
npm run dev
```

3. Открыть адрес, который покажет Wrangler.
4. Войти как `admin` / `csmarketing`.

Перед публикацией рекомендуется заменить пароль на более длинный. Если нужно оставить именно `csmarketing`, технически это поддерживается.

## Публикация в Cloudflare

1. Авторизоваться:

```bash
npx wrangler login
```

2. Создать D1:

```bash
npx wrangler d1 create cs-marketing
```

Скопировать `database_id` в `wrangler.toml`.

3. Создать таблицы:

```bash
npm run db:remote
```

4. Задать пароль:

```bash
npx wrangler secret put ADMIN_PASSWORD
```

При запросе значения ввести:

```text
csmarketing
```

5. Создать длинный случайный ключ подписи сессии. Например:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопировать результат и сохранить:

```bash
npx wrangler secret put SESSION_SECRET
```

6. Добавить секреты интеграций по мере подключения:

```bash
npx wrangler secret put YANDEX_TOKEN
npx wrangler secret put METRIKA_COUNTER_ID
npx wrangler secret put WEBMASTER_HOST_ID
npx wrangler secret put DIRECT_TOKEN
npx wrangler secret put DIRECT_CLIENT_LOGIN
```

`DIRECT_CLIENT_LOGIN` нужен не во всех конфигурациях Директа.

7. Опубликовать:

```bash
npm run deploy
```

## Доступы Яндекса

### Яндекс Метрика

Нужен OAuth-токен с доступом `metrika:read` и ID счётчика.

### Яндекс Вебмастер

Нужен OAuth-токен с доступом к Вебмастеру и `host-id` сайта. Worker автоматически получает `user_id` через API.

### Яндекс Директ

Нужен OAuth-токен, а приложение должно иметь одобренный доступ к API Директа. Адаптер использует Reports API v5 и собирает кампании за последние 30 дней.

## Безопасность

Не вставляйте OAuth-токены, пароль или `SESSION_SECRET` в `app.js`, HTML или публичный репозиторий. `.dev.vars` уже добавлен в `.gitignore`.

Статические HTML/CSS/JS-файлы приложения остаются публичными техническими ресурсами сайта, как у любого веб-приложения. Реальные маркетинговые данные защищены на API-уровне и без сессии не выдаются.

## Импорт файлов

В разделе «Интеграции» выберите источник и загрузите CSV/XLSX/JSON. Приложение распознаёт русские и английские названия типовых колонок.

Примеры:

- Сайт: `Дата`, `Визиты`, `Посетители`, `Отказы`, `Глубина`, `Конверсии`;
- SEO: `Запрос`, `Показы`, `Клики`, `CTR`, `Позиция`, `Изменение позиции`;
- Реклама: `Кампания`, `Показы`, `Клики`, `Расход`, `Конверсии`;
- Соцсети: `Канал`, `Публикация`, `Дата`, `Охват`, `Реакции`;
- Email: `Рассылка`, `Дата`, `Отправлено`, `Открытия`, `Клики`, `Отписки`, `Ошибки`.
